## 3. Email subscriber system
Do not connect a dead frontend form.

Production flow:
1. Visitor chooses Join LeeWay Updates / Pocket Agent Lee Early Access.
2. Collect email; first name is optional.
3. Require explicit marketing/update consent. Do not pre-check it.
4. Keep analytics consent separate.
5. For the simplest public compliance boundary, restrict subscription collection to adults 18+ while general site viewing remains open.
6. Send a confirmation message.
7. Confirm subscription before regular campaign/update delivery (double opt-in is preferred).
8. Store consent timestamp, consent version, email, status and source page.
9. Every marketing/update email must provide a working unsubscribe route.
10. Maintain suppression state after unsubscribe; do not silently re-add the address.
11. Do not sell or share the list for advertising.
12. Do not claim automation is live until the backend, sender identity, unsubscribe handler and storage are tested.

Backend gate:
GitHub Pages cannot securely own email credentials or a subscriber database by itself. Reuse an already-authorized LeeWay public backend if one is proven. If none exists, creation of a new public backend is a separate architecture/authority decision.

Commercial-email blocker:
Before production marketing/update email is enabled, configure the sender's valid physical postal address (registered PO box/private mailbox is acceptable where legally applicable), accurate From/Reply-To identity and unsubscribe processing. Do not invent this address.

## 4. Usage analytics / visitor journey
Default: OFF until consent and storage are implemented.

Use first-party, purpose-limited analytics. Do not use analytics consent as a condition for entering the Digital Brain.

Allowed event classes after consent:
- page/view identifier
- project/evidence identifier
- category entered
- dwell-time bucket
- scroll-depth bucket: 25/50/75/100
- CTA click: contact / GitHub / YouTube / Pocket Agent Lee / project open
- device class and viewport class
- coarse performance metrics
- consent version
- random first-party session identifier

Do NOT collect for analytics:
- microphone recordings
- speech transcripts
- Agent Lee prompts or generated conversation text
- typed form text other than the explicit signup fields
- camera data
- precise location
- contact lists
- cross-site advertising identifiers
- browser fingerprint
- keystroke/session-replay recordings
- hidden clipboard data

Identity separation:
Do not automatically join subscriber email identity to browsing history. If personalized follow-up is ever desired, require a distinct informed consent and document that purpose.

Privacy controls:
- Essential only / Allow analytics choices must be equally understandable.
- Honor withdrawal immediately for future collection.
- Support applicable browser opt-out preference signals such as Global Privacy Control when required.
- Maintain a current privacy notice describing what is collected, why, retention, processors/providers, contact method and deletion/opt-out choices.
- Keep a short retention window unless a longer period is justified; proposed analytics retention: 90 days.
- Keep aggregate statistics after deleting raw session events where practical.
